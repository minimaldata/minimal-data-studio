# Editable dataset drafts (preview)

Use **Edit a copy…** on an editor result, or **New dataset…** in Files. Drafts are separate snapshots: source files, source tables, and executed queries are not edited. Copying uses the entire retained result, regardless of result filters/pagination. The editor explicitly refuses results larger than 10,000 rows, 100 columns, or 100,000 cells; it never truncates them.

Drafts autosave to the project's DuckDB `_studio.drafts` table, with revision checks to prevent another window overwriting changes. Save status is visible, a Save draft action can retry a failed request, and navigating away warns while edits are unsaved. Draft tabs can close without deleting the draft; reopen from Editable drafts. Hover over a draft to reveal its trash button. Deletion asks for confirmation, removes the draft and its history, and leaves exported CSVs, created tables and source data untouched. Revision checks block deletion of a draft changed in another window; pending autosaves cannot recreate it. Undo/redo lasts for the current page session (20 snapshots); the last 200 edit-log entries persist.

## Spreadsheet and CSV source

Spreadsheet editing supports cells, adding/removing rows or columns, column renaming, and explicit use of the first row as headers. Click/drag or Shift-click to select a rectangle; arrows move selection and Shift-arrows extend it. Single-click highlights a cell; arrow keys navigate between highlighted cells. Double-click, F2, or typing edits a cell; arrows then move the text cursor. Return commits and selects the cell below; Shift-Enter inserts a line break. Delete clears selected values. Clipboard copy/paste uses quoted tab-separated text; commas alone never split cells. Dragging near a scrollable grid edge scrolls the current page while extending the selection. Multi-row or multi-column clipboard data fills cells even if the destination cell is being edited; quoted multiline values remain one cell. Pasting grows the grid when necessary and asks before replacing populated values. A single value fills a selected rectangle. A multi-cell block must match the selected rectangle or start at one selected cell. One paste is one undo action. Formulas are not evaluated.

Raw CSV remains intact when merely switching views. Editing the grid serializes using commas, proper escaping, and LF line endings. Empty values are quoted to preserve single-column empty rows. Invalid CSV remains editable in CSV source; switching to the spreadsheet explains structural problems instead of repairing or dropping rows. CSV has no intrinsic types or universal NULL representation. SQL NULLs copied into a draft become empty fields, clearly disclosed in the draft; the missing-values checkbox controls table creation.

## Check and create

Text is the default. Types include Text, Number (approximate DOUBLE), Whole number (BIGINT), Date, DateTime, and True/false. Date accepts only YYYY-MM-DD. DateTime accepts YYYY-MM-DD HH:MM:SS with a 24-hour clock and creates a timezone-free TIMESTAMP. Existing draft format preferences do not override these rules; nonconforming values remain intact and are flagged. Type selection never rewrites draft values. **Check draft** validates all values on demand, and runs automatically after a column type changes. Cell keystrokes do not trigger checks. Structural CSV parsing occurs on switching back to Spreadsheet, checking, or saving CSV. Typed creation always validates again on the server.

Column headers have a soft error background, cells an outline and `!`; selecting a cell explains the issue and possible corrections. Technical details include a parameterized DuckDB conversion and its error, or an explanation when DuckDB would permissively convert a value that Studio rejects (e.g. rounding a decimal to an integer). Findings are capped at the first 500 cells, with a full issue count. Edits invalidate overall check status and clear affected cell findings; unchanged findings remain until the next check.

**Create table…** requires a successful current check and a new name, then atomically creates a snapshot with chosen types. Existing tables/views cannot be replaced. A provenance comment records the draft ID, source query context and recent edit history. Under the hood shows the conversion SQL using a temporary input placeholder.

**Save CSV…** writes a new file in `exports/`, refusing existing filenames. Type errors do not prevent saving syntactically valid CSV. It does not create a database table or carry type metadata into CSV. Draft values starting with spreadsheet formula characters remain literal text here; other spreadsheet applications may interpret them when opening an exported CSV.
